# Qadam — корпоративный портал Luxury Servis / Darian

Единая точка входа для сотрудников: **Мой путь** (рост и оценка 360°, бывший Qadam), **ЗП и KPI**, **«Пришёл»**, **ЧАВО / база знаний**, **Помощник оператора** (Darian·Assist) и **админка**. Русский и узбекский, светлая и тёмная темы, адаптивно (телефон и ПК).

Стек по ТЗ (раздел 11): модульный монолит — TypeScript, Node 22, Fastify, PostgreSQL 16; интерфейс на Svelte 5 + Vite (стартовый JS ≈ 43 КБ gzip при бюджете 100 КБ).

## Сотрудники: импорт из Excel

Админка → Сотрудники → **Импорт из Excel**: файл с колонками «ФИО», «Должность», «Дата приёма» (можно тот же, что для зарплаты). Показывается предпросмотр, затем создаются учётные записи: логин латиницей из ФИО (`kosimjonov.davron`), пароль из 6 цифр, роль по должности (супервайзер и руководитель получают роль «Руководитель»). Пароли показываются один раз и скачиваются списком (CSV для Excel); при первом входе сотрудник задаёт свой пароль. Существующие ФИО пропускаются.

## Помощник оператора: как добавлять и править данные

Исходный HTML (`assist/source/darian-operator-assistant.html`) разобран скриптом `scripts/import-assist.mjs`: все данные (деревья неисправностей, коды Ziffler/Immer, сервисные центры, фразы RU/UZ, гарантии, сценарии звонков, тренажёр и т. д. — 28 коллекций) лежат в PostgreSQL, а сама страница (`assist/template.html`) собирается сервером с данными из базы.

**Админка → Помощник оператора:**
1. Выберите раздел (например, «Сервисные центры») и элемент слева.
2. Правьте во вкладке **«Форма»** (универсальный редактор: поля, списки, таблицы со вставкой из Excel, вложенные деревья) или **«JSON»**.
3. **Сохранить** — правка попадает в рабочую копию. Операторы её **ещё не видят**.
4. На главной странице раздела — **«Опубликовать выпуск»** (с заметкой). Только тогда помощник обновляется у всех.
5. Любой прошлый выпуск можно сделать активным (**«Сделать активным»**) или вернуть и рабочую копию тоже (**«Вернуть всё»**).
6. Для массовых правок: у каждой коллекции есть **экспорт/импорт JSON и Excel** (вложенное хранится в ячейке как JSON).

**Язык клиента RU / UZ и кириллица.** В шапке помощника переключатель **RU | UZ** и кнопка **Кир / Lat**. В режиме UZ вместо русских фраз «что сказать клиенту» показываются узбекские; все узбекские тексты (фразы, подсказки к симптомам, советы по кодам) показываются кириллицей, кнопки «копировать» копируют то, что видит оператор. Выбор запоминается в браузере. Данные в базе остаются латиницей (поиск понимает оба написания), а перевод делает `assist/patch/uzcyr.js` на показе. Ошибочный перевод слова исправляется в админке: Помощник оператора → «Исключения: латиница → кириллица» (слово латиницей → как показывать; `=` — оставить латиницей, как Wi-Fi). Интерфейс помощника (меню, инструкции оператору) остаётся русским.

Если владелец выпустил новую версию HTML целиком: `npm run assist:import путь/к/файлу.html && npm run assist:load` — рабочая копия заменяется и создаётся новый выпуск (прошлые остаются в истории).

## Локальный запуск

```bash
npm install
cp .env.example .env            # DATABASE_URL на ваш PostgreSQL 16
npm run migrate -w server
npm run seed -w server          # демо-данные: dilnoza, rustam (руководитель), hr, buh, editor, op1…op4, пароль demo12345
npm run dev:server              # API на :3000
npm run dev:web                 # интерфейс на :5173 (проксирует /api и /assist)
npm test                        # 12 интеграционных тестов (нужен PostgreSQL, БД portal_test пересоздаётся)
```

Администратор создаётся при первом запуске (`ADMIN_LOGIN` / `ADMIN_PASSWORD`; без пароля — случайный, он печатается в логе).

## Деплой на Railway

Ветка для деплоя — **`main`**. Нужно всего три действия:

1. Railway → *New Project* → *Deploy from GitHub repo* → `AzizRas/Corporate-Portal` (ветка `main`).
2. В проекте *+ New → Database → Add PostgreSQL*, затем в сервисе портала *Variables → New Variable → Add Reference → Postgres → `DATABASE_URL`*.
3. В *Variables* добавьте `ADMIN_PASSWORD` (ваш пароль администратора; логин `admin`). Затем *Settings → Networking → Generate Domain*.

Сборка, миграции базы и загрузка контента помощника выполняются сами при первом запуске (`railway.json`, проверка `/healthz`). Если `ADMIN_PASSWORD` не задан, пароль администратора будет создан случайным и напечатан в логах первого запуска.

Позже, по желанию: *Volume* и переменная `UPLOAD_DIR=/data/uploads` (нужны только если включите селфи в «Пришёл», иначе фото пропадут при перезапуске) и ежедневные бэкапы PostgreSQL.

## Безопасность

- Права проверяются на сервере; отказ доступа пишется в журнал (`access_denied`). Сотрудник получает только свою ведомость, руководитель — свод без имён.
- Пароли — scrypt, сессии — случайный токен в httpOnly-куке (в базе хранится только хэш).
- Селфи — только съёмка камерой в момент нажатия, срок хранения задаётся в админке (по умолчанию 30 дней), удаление пишется в журнал, при увольнении фото удаляются.

### Улучшения по аудиту (ветки `fix/week1`, `fix/week2`, `fix/week4`)

- **Кэш и сборка:** `index.html` отдаётся с `no-cache`, файлы `/assets/*` — на год (`immutable`); устаревший хэшированный файл даёт 404, а не страницу. Первый экран грузит ~78 КБ gzip, остальные разделы подгружаются при первом открытии; если после выкладки вкладка не нашла файл раздела, страница один раз перезагружается.
- **Заголовки:** `Content-Security-Policy` (строгая для интерфейса; `/assist` со своими встроенными скриптами), `X-Frame-Options: DENY`, `Strict-Transport-Security` (в продакшене). Тема до первой отрисовки вынесена в `/theme.js`, чтобы в `index.html` не было встроенных скриптов.
- **Вход:** не больше 20 неверных попыток за 10 минут с одного IP (`LOGIN_IP_MAX`), пауза учётной записи после 5 ошибок подряд: 30 с, 1, 2, 4, 8 мин, не дольше 15. Хэш пароля считается асинхронно. Смена пароля закрывает остальные сеансы; в профиле есть «Выйти на других устройствах». Если портал стоит за прокси, проверьте, что `X-Forwarded-For` задаёт прокси, а не клиент.
- **Закрытые разделы** закрыты и на сервере (список — `GATES` в `server/src/access.ts`), а не только убраны из меню. Поиск по порталу не отдаёт статьи закрытого раздела.
- **Кэши в памяти** (меняются переменными): пользователь по токену 30 с (`USER_CACHE_MS`), расчёт панели руководителя 10 мин (`PANEL_CACHE_MS`), пул БД 20 соединений (`DB_POOL_MAX`). Изменения в админке, выход и закрытие сеансов сбрасывают кэш пользователя сразу.
- **ИИ:** с ключом OpenRouter сначала идёт модель функции, запасные из `OPENROUTER_MODEL` — только при сбое; рассуждение модели включено только у аналитика и ИИ-оценки; на одну модель 20 с, на всю цепочку 60 с (`AI_ATTEMPT_MS`, `AI_CHAIN_DEADLINE_MS`); общая часть подсказки кэшируется у провайдера; ответ наставника идёт потоком (`POST /api/growth/mentor/stream`); расход за месяц хранится в памяти, параллельные запросы резервируют бюджет; в «Админке → ИИ» задаётся суточный лимит запросов на человека.
- **Выгорание:** два индекса 0–100 по правилам, без ИИ и без новых таблиц — «нагрузка» (переработки, работа без выходных, давно не было отпуска, пропуск пауз, ночная активность, рост обращений к помощнику) и «вовлечённость» (активность, результаты, настроение, просрочки). Сигнал «стоит поговорить» — прежние правила или высокая нагрузка при вовлечённости, падающей две недели подряд; виден без ИИ прямому руководителю и HR. Тренд за 8 недель — в карточке сотрудника, сводка по подразделениям — у HR и админа, свой индекс и советы — у самого сотрудника на главной. В ИИ уходят только id, должность и показатели.
- **Использование разделов** (Админка → «Использование разделов»): доли подразделений, открывших раздел за 30 дней, кандидаты на скрытие и «вынести в меню», тренд по еженедельным снимкам (хранятся в `settings`), вывод недели от ИИ, применение одной кнопкой.
- **График:** массовые действия не трогают заявки сотрудников и прошедшие дни (кроме админа), показывают итог и дают «Отменить»; «Стандарт» сначала показывает, у скольких сбросятся выходные; авто-выходные раскладываются по выбранной команде и обходят праздники (фиксированные даты Узбекистана + свои в «Праздники»).
- **Интерфейс:** свои окна вместо `confirm/alert/prompt`, серые полосы загрузки, пустые состояния и понятные ошибки, токены в `web/src/tokens.css`, плотность «обычная/компактная» (в профиле), контраст AA проверяется `web/scripts/contrast.mjs` и тестом. Число встроенных `style="…"` зафиксировано тестом и может только уменьшаться.
- **Файлы в хранилище (S3):** резюме, вложения чата и селфи при приходе можно хранить в S3-совместимом хранилище (AWS S3, Cloudflare R2, MinIO, Backblaze B2): задайте `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` (и при необходимости `S3_REGION`, по умолчанию `auto`). Без них всё работает как раньше (резюме в базе, остальное на диске `UPLOAD_DIR`). Старые резюме из базы переносит `npm run storage:migrate -w server` (безопасно повторять; чтобы вернуть место в базе, потом выполните `VACUUM FULL hire_resumes`). Старые файлы чата с диска продолжают читаться. Миграция `021_file_storage.sql` лишь ослабляет ограничение и добавляет столбец.
- **Меню:** семь разделов первого уровня (Главная, Чат, Знания, Обучение, Развитие, Работа, Управление), внутри — вкладки; профиль открывается из карточки человека и «Ещё». Состав разделов — `HUBS` в `web/src/lib/nav-core.ts`.
- **Удаление с «Отменить»:** сообщения чата, записи ленты, рекомендации и цели удаляются через 8 секунд после нажатия, пока не нажали «Отменить» (закрыли вкладку раньше — запись останется). Остальные удаления спрашивают подтверждение своим окном.
- **Стили и значки:** статические `style="…"` перенесены в `web/src/inline.css` (создан скриптом, правится не вручную), динамические — `style:свойство={…}`; исключение — окно печати оффера. Значки — только линейный набор `Icon` (эмодзи остались у опроса настроения, реакций чата и напоминаний об отдыхе). На телефоне таблицы `.table` показываются карточками.

## Развитие сотрудников (перенос из Qadam)

Раздел **Развитие** (`#/growth`): опросы 360°, беседа 1:1 и ИПР, ИИ-наставник, лента, чат; у руководителей и HR — **Кадровый резерв** и карточка сотрудника.

ИИ-наставник и «черновик рекомендаций» работают при переменной `OPENROUTER_API_KEY` (модели: `OPENROUTER_MODEL` (можно несколько через запятую — запасные), по умолчанию `anthropic/claude-sonnet-4.5`) либо `ANTHROPIC_API_KEY`.

## Поиск помощника

Понимает окончания и опечатки, разговорные названия техники, узбекский (латиница и кириллица), «одно понятие — разные слова» («гудит» = «shovqin»), коды ошибок (E6, Е-09, d3), модель с наклейки и телефон СЦ. Запросы пишутся в журнал; админка → Помощник оператора показывает «что искали и не нашли». Узбекские фразы к исходам (`SAY_UZ`) — автоперевод, их должен проверить носитель языка. Старая страница `/assist` оставлена как запасная.

## Роли и разделы (второй релиз)

Иерархия: оператор (`employee`) → старший оператор (`senior`) → супервайзер (`manager`) → руководитель отдела (`head`). Старший оператор подтверждает выходные операторов, супервайзер и выше — выходные старших и постоянный график. Зоны роста видят сотрудник, супервайзер, руководитель отдела и админ; личную цель — только сотрудник и руководитель отдела.

- **Чат** — главный раздел: каналы, ответы, @упоминания, непрочитанное; **Новости** — объявления, комментарии, дни рождения.
- **График** — смены и выходные по заявке; при входе портал напоминает отметиться (без времени и опозданий).
- **Обучение** — план новичка на 10 дней (редактируется в Админка → Обучение), тренажёр диалогов, интервью «готов к линии», допуск.
- **Тесты** (PAEI, конфликт, стресс, мотивация, выгорание, знание продукта, клиентоориентированность), **Библиотека**, **напоминания о паузах** (Админка → Напоминания).
- ИИ работает с `OPENROUTER_API_KEY` или `ANTHROPIC_API_KEY`; без ключа — встроенный режим. Узбекские тексты нужно проверить носителем.

## Волны A–E: структура, чат, ИИ-ядро, обучение порталу

- **Меню** — 6 групп (Главная, Обучение, Знания, Люди, Профиль, Управление); поиск Ctrl+K по ЧАВО, тестам, людям, чатам, разделам; если ничего не найдено — ответ ИИ по базе знаний со ссылками, иначе вопрос уходит в **очередь вопросов** (`#/queue`).
- **ЗП и KPI** — в «Профиль → ЗП и KPI»: суммы скрыты, показ по кнопке на 30 секунд, каждый показ пишется в журнал; сервер не отдаёт суммы без запроса «Показать»; у стажёров раздел закрыт до перевода в штат.
- **Структура компании** (`#/structure`) — дерево «руководитель → отдел → подотдел → группа»; внешнее подразделение видит только разрешённые разделы. Права строятся по ветке дерева. Состояния: стажёр → штат, перевод с даты, отпуск/больничный (с делегированием прав), увольнение (доступ и фото удаляются сразу), архив, восстановление, полное удаление (админ, ввод имени). Excel-импорт/экспорт, журнал изменений.
- **Чат** — общий, отделы и внешние подразделения (состав по дереву), личные и группы с ролями (владелец/админ/участник), файлы, ответы, @, закреплённое, поиск, «прочитано», тихие часы. Личные чаты админ не читает.
- **ИИ** (`OPENROUTER_API_KEY` или `ANTHROPIC_API_KEY`; модель `OPENROUTER_MODEL`): единое ядро с месячным лимитом стоимости, кэшем, журналом и оценкой ответов («Админка → ИИ»; там же «Стиль общения», общий для всех ролей). Роли: наставник, аналитик руководителя (панель в «Команде»), редактор контента (`#/editor`: только черновики, публикует человек, есть откат), помощник супервайзера (`#/assistant`). Зарплата и фото во внешнюю модель не передаются. Без ИИ портал работает: руководитель видит обычную статистику, админ видит причину.
- **Обучение порталу** — тур по ролям (из профиля можно пройти заново), чек-лист «Первые шаги», «?» на страницах, раздел «Как пользоваться порталом» и подсветка нужной кнопки; статистика прохождения — «Админка → Обучение порталу».
- Тесты: `cd server && npx tsx --test --test-concurrency=1 test/*.test.ts`. Узбекские тексты нужно проверить носителем.

## Окно-помощник оператора

Кнопка ✦ в правом нижнем углу открывает компактное окно (на телефоне — над нижней панелью). Оператор пишет вопрос или ситуацию с клиентом:
1. ищем в базе знаний → ответ с источниками и «готовый ответ клиенту» (кнопка «Скопировать»);
2. в базе нет — ИИ даёт осторожный совет из общих знаний с пометкой «не из базы компании — проверьте» (поиск в интернете включается моделью с суффиксом `:online` в `OPENROUTER_MODEL`);
3. не уверен или ИИ выключен — вопрос сохраняется в очередь руководителя (`/api/questions/queue`), повторы склеиваются.

В ИИ не уходят телефоны и длинные номера клиентов (маскируются), зарплата и фото. Без ИИ окно показывает найденные статьи и передаёт вопрос руководителю. Эндпоинт — `POST /api/search/chat`.

### Окно-помощник: база, данные платформы и ИИ (параллельно)

Каждое сообщение отправляется двумя запросами одновременно:
- `POST /api/search/chat/kb` — мгновенно, без ИИ: статьи базы знаний и данные платформы (справочник «кто есть кто», чтение, обучение, активность, перерывы, метки);
- `POST /api/search/chat` — ИИ получает вопрос, найденные статьи и те же данные платформы, выбирает источник (`kb` / `data` / `general` / `none`) и сразу отдаёт готовый ответ.

Права на данные о людях проверяются на сервере (`server/src/assist-data.ts`): оператор видит себя, руководитель — свою ветку, HR и админ — всех; справочник (должность, отдел, руководитель) открыт всем. Метки «признаки перегрузки», «настроение снижается», «стоит поговорить» — только прямому руководителю и HR, только при включённом ИИ-аналитике (как на панели); ответы опроса настроения чужим не показываются. Зарплата и фото в этот контекст не входят. Показ данных других людей пишется в журнал (`assist_data`), отказ — `access_denied`. Вопросы о людях в очередь вопросов не попадают.

### Схема компании (`#/structure`)

Вкладка «Схема» открывается первой и показывает всех сотрудников по подразделениям (колл-центр, сервис-центр, склад, HR и бухгалтерия, внешние). Три вида, переключатель запоминается: «Схема» (карточки-блоки со связями), «Карта» (узлы-аватары слева направо с пунктирными связями), «Подразделения» (карточки подразделений со списком людей, на телефоне открывается по умолчанию). У каждого подразделения свой цвет, сверху фильтр по подразделению и поиск по имени и должности. Клик по узлу открывает боковую панель: руководитель, сотрудники, вложенные узлы. Данные: `GET /api/org/chart` (имя, должность и фото видны всем, как в справочнике; контакты не отдаются; отпуск видят только те, кто открывает узел; внешние подразделения видят HR и админ). Прежнее дерево с правкой, переводами, отпусками и увольнением осталось во вкладке «Управление». Справочные подразделения («Внешний отдел», админ и HR): вышестоящие компании, партнёры, чужие отделы. Рисуются отдельно от дерева, без линий и стрелок; у каждого контакты (сотрудник портала или человек вне портала: имя, должность, телефон, email, фото JPEG/PNG до 1,5 МБ). Таблицы `org_ref_units` и `org_ref_people` (миграция `018_extras_refs.sql`, только новые таблицы).

## График работы (`#/schedule`)

Стандарт компании: 9:00–19:00 и один плавающий выходной в неделю (часы задаёт админ или HR, настройка `schedule_policy`; у новых сотрудников по умолчанию так). Вкладка «Команда»: сетка месяца по неделям, показатели (сотрудники, заявки, без выходного на неделе, минимум на смене), строка «На смене» по дням, предупреждение у тех, у кого на неделе нет выходного. **Массовые действия:** выбор ячеек (клик, Shift, галочка строки, число над днём, номер недели) → выходной, рабочий день, вернуть по графику, «Стандарт 9–19» для выбранных, автоматическая расстановка плавающих выходных на период (с предпросмотром, равномерно по дням недели), повтор выходных одной недели на других, массовое решение по заявкам. API: `/api/schedule/bulk`, `bulk-pattern`, `auto-off`, `copy-week`, `decide-bulk`, `policy`. Таблицы не менялись. Исправлена ошибка: в месяцах из 30 дней и в феврале страница графика не открывалась.

## Найм (`#/hire`)

Вакансии, воронка кандидатов по этапам, база кандидатов, заявки руководителей, встречи, офферы и отчёты. Пункт «Найм» в группе «Люди».

- **Роли:** рекрутер — роль `recruiter` (новая) или `hr`, плюс админ; заказчик — `manager` или `head`. Заказчик видит только вакансии, где он участник или автор заявки, и кандидатов на них; контакты кандидатов скрыты (включается в Найм → Настройки). Внутренний кандидат (сотрудник портала) скрыт от тех, кто руководит его веткой.
- **Воронка:** этапы, причины отказа, источники, теги, шаблоны писем, поля форм заявки и оффера, праздники — Найм → Настройки (админ). Перенос кандидата защищён от одновременной правки (409 `stale`), история этапов пишется всегда.
- **Подбор среди сотрудников:** на вакансии с должностью «Подбор» показывает сотрудников, нацеленных на неё, с готовностью из «Моего пути».
- **Отчёты:** воронка, срок закрытия вакансий в рабочих днях (будни и праздники, паузы вычитаются), рекрутеры (наём делится поровну между рекрутерами вакансии), скорость по этапам.
- **Данные:** миграция `017_hire.sql` только добавляет 21 таблицу `hire_*`; существующие таблицы и данные не меняются. Резюме (Word, PDF, TXT, RTF, ODT, PNG, JPG до 5 МБ) лежат в базе; просмотр записывается в журнал; админ может обезличить или удалить кандидата.
- **Сводка просрочек:** раз в сутки рекрутерам вакансии приходит уведомление, если кандидат дольше лимита этапа.
- Письма кандидатам открываются в почтовой программе (`mailto:`), с сервера не отправляются. ИИ в найме не используется. Узбекские тексты нужно проверить носителем.
- **Календарь встреч** (вкладка «Встречи»): месяц, неделя, список. Видно время (по часам компании, Ташкент), кандидата, вакансию и участников с ролью: HR, рекрутер или руководитель. Встречу назначают в карточке кандидата; в календаре её можно отметить проведённой или отменить.
- **Кандидат из файла:** «Добавить кандидата» → «Из файла» принимает Word (docx, старый doc), PDF, ODT, RTF и текст до 5 МБ. Сервер достаёт текст и подставляет ФИО, телефон, email, должность, город, дату рождения и ожидаемую зарплату (`POST /api/hire/import`, `server/src/modules/hire-parse.ts`). Ничего не сохраняется само: рекрутер проверяет поля, при совпадении телефона, email или имени видит возможные дубли. Скан или картинка без текста откроют пустую форму, файл прикладывается как резюме. Вручную кандидата тоже можно создать.
- **Разбор резюме:** всё, что файл содержит и что не легло в поля, показывается кусками; у каждого выбор, куда подставить (поле формы, Telegram, WhatsApp, Instagram, LinkedIn, сайт, доп. телефон или email, город, место работы, образование, навыки, языки, зарплата, заметка). Hh-подобные PDF читаются по строкам. Сохраняется в таблицу `hire_applicant_extra` и показывается в карточке кандидата («Контакты и данные»); заказчик контакты не видит, пока админ не откроет.
- **Резюме как документ, ИИ и шаблоны:** при загрузке файла резюме разбирается в структуру (желаемая должность и условия, опыт по местам работы с обязанностями, образование, навыки, языки, курсы, «о себе», дополнительные сведения) и сохраняется в `hire_applicant_profile` вместе с полным текстом файла, ничего не теряется. Карточка кандидата открывается как резюме, без раскрывашек. «Исходный текст» можно поправить и разобрать заново; для нестандартных резюме есть разбор с ИИ. **ИИ-оценка** (кнопка в карточке, роль ИИ «Помощник рекрутёра» в Админка → ИИ): вердикт, баллы, сильные стороны, пробелы, вопросы для собеседования и рекомендация (пригласить, резерв, не продолжать, другая вакансия). Принципы: ИИ только советует, решение за человеком; в модель не уходят имя, контакты, пол, возраст, гражданство и место жительства; оценка только по рабочим критериям и только по резюме, без домыслов; каждая оценка хранится с причинами (`hire_ai_reviews`) и пишется в журнал; предупреждение, если нет согласия кандидата. **Шаблоны сообщений** (25 случаев на русском и узбекском, `server/src/hire-templates.ts`): Telegram, WhatsApp, почта; имя, вакансия, время и место встречи подставляются сами. Telegram не умеет принимать готовый текст по ссылке, поэтому текст копируется в буфер и открывается чат.
- **Дизайн:** минимализм в палитре Hunter Black, Flow Blue и Electric Violet, шрифт Onest (названия шрифтов бренда на странице бренда не указаны, Onest — свободная замена с кириллицей). Тёмная и светлая темы, боковая панель всегда тёмная. Вакансия открывается списком (этапы вкладками, кандидаты слева, карточка справа) или доской. Цвета меняются в токенах `web/src/app.css`.
- **Библиотека и тесты** открыты всем подразделениям и ролям, админ их закрыть не может (`ALWAYS` в `server/src/access.ts`).
- Тесты: `cd server && npx tsx --test --test-concurrency=1 test/hire.test.ts`.

### Доступ к разделам по подразделениям

У колл-центра, сервис-центра, склада, HR, рекрутеров и бухгалтерии свой набор разделов (`server/src/access.ts`). Профиль определяется ролью (`accountant` → бухгалтерия, `hr`, `recruiter`), иначе подразделением; у админа и у сотрудников без подразделения доступно всё, как раньше. Набор по умолчанию: колл-центр — всё; сервис-центр и склад — без тренажёра и готовности к линии; HR — найм, план обучения (адаптация), развитие, чат, команда, структура, график, задачи; без помощника оператора, тренажёра, ЧАВО, тестов и библиотеки; рекрутер и бухгалтерия — рабочее минимум (сводка, новости, чат, задачи, график, ЗП). Помощник оператора (включая окно ✦), тренажёр и готовность к линии закрываются и на сервере (403 `section_forbidden`, запись в журнал), остальные разделы скрываются в меню и по прямой ссылке. Найм открыт ролям `hr`, `recruiter`, `manager`, `head` независимо от набора. Админка → «Доступ к разделам» меняет набор (хранится в `settings`, ключ `section_access`; схема БД не меняется), кнопка «По умолчанию» возвращает исходный. Тесты: `test/access.test.ts`.

## Чат как в мессенджере, PWA, push, кадровые сервисы, 2FA (ТЗ №2)

- **Чат** (`web/src/chat/`): пузыри с «хвостиком», время и галочки прочтения внутри пузыря, список чатов с превью и временем, реакции (👍 ❤️ 🔥 😂 👏 🎉), правка в течение суток (пометка «изм.»), пересылка, стикеры (16 векторных, `web/src/chat/stickers.ts`) и панель эмодзи, вставка скриншота из буфера (Ctrl+V) и перетаскивание файла, черновики, «печатает…», «в сети». Меню сообщения — клик или правая кнопка по пузырю; ↑ в пустом поле правит последнее своё сообщение.
- **Реальное время**: `GET /api/chat/stream` (SSE). Событие говорит только «в канале что-то изменилось», клиент сам забирает данные обычным запросом, поэтому права проверяются как раньше. Опрос остаётся редкой страховкой (раз в ~30 с при живом потоке). Шина событий (`chatBus`) в памяти процесса: при нескольких экземплярах сервера понадобится Redis/Postgres LISTEN.
- **PWA и Web Push**: `web/public/manifest.webmanifest`, `sw.js` (оболочка и файлы `/assets/` офлайн, API не кэшируется), иконки делает `node scripts/make-icons.mjs`. Push включается переменными `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (ключи: `npx web-push generate-vapid-keys`); без них кнопки в настройках нет, портал работает как раньше. Уходят уведомления колокольчика и личные сообщения с учётом настроек (тип, тихие часы, заглушённые чаты).
- **Справки и отпуска** (Профиль → «Документы и отпуск», «Люди → Отпуска» для руководителей): справка с места работы в PDF (русский/узбекский, шрифт DejaVu, QR-код на `/verify-cert/<код>` — публичная проверка показывает только ФИО, должность и дату; HR может отозвать, не больше 5 в сутки). Адрес проверки строится из `PUBLIC_URL`. Заявка на отпуск → согласование руководителем/HR → запись `user_leaves` (её уже учитывают график и выгорание); календарь подсвечивает пересечения отпусков у людей одной должности.
- **2FA (TOTP)**: Профиль → Настройки. Секрет шифруется (`TOTP_KEY`), есть 8 одноразовых резервных кодов, повтор кода не проходит, ошибки кода считаются как ошибки пароля. Для `admin` и `accountant` обязательна: в боевом окружении (или при `TOTP_ENFORCE=1`) до настройки доступны только вход, выход и сама настройка; `TOTP_ENFORCE=0` выключает требование. Потерял телефон и коды — админ: `POST /api/org/users/:id/2fa-reset`.
- **Эксплуатация**: `GET /healthz` отдаёт `status`, `db`, `storage`, `uptime`; `TRUST_PROXY` (`true` или список адресов) управляет доверием к `X-Forwarded-For` — на Railway задайте `TRUST_PROXY=true`, иначе проверка офисного Wi-Fi и лимит входа увидят адрес прокси.
- Миграции: `023` (чат), `024` (push), `025` (справки, заявки), `026` (2FA). Тесты: `chat-telegram`, `push`, `hr-requests`, `totp`.
